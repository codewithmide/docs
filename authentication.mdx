## API Authentication

FossaPay uses API keys to authenticate requests. You can view and manage your API keys in the [FossaPay Dashboard](https://dashboard.fossapay.com/settings?tab=api-keys).

<Warning>
  **Production only.** FossaPay currently uses production systems for every API request, so keep your live API keys secure and only test with amounts and actions you are comfortable running against production.
</Warning>

## Getting Your API Keys

1. Sign up or log in to your [FossaPay Dashboard](https://dashboard.fossapay.com)
2. Navigate to **Settings** → **API Keys**
3. Copy your **Live Key**
4. Use the live key for all API requests

## Making Authenticated Requests

Include your secret key in the `x-api-key` header of your API requests:

```bash
curl https://api-production.fossapay.com/api/v1/wallets/fiat/create \
  -H "x-api-key: fk_production_DTKUG..." \
  -H "Content-Type: application/json"
```

### Authentication Header Format

```
x-api-key: fk_production_DTKUG...
```

## API Key Format

FossaPay API keys follow this format:

- **Production Key**: `fk_production_DTKUG...`

## Request Headers

Every API request should include these headers:

| Header | Value | Required |
|--------|-------|----------|
| `x-api-key` | `fk_production_DTKUG...` | Yes |
| `Content-Type` | `application/json` | Yes |
| `X-Idempotency-Key` | Unique request identifier | Required when creating a checkout |

### Example Request

```javascript
const axios = require('axios');

const response = await axios.post(
  'https://api-production.fossapay.com/api/v1/wallets/fiat/create',
  {
    customerId: 'cus_123456789',
    walletName: 'Main Wallet',
    walletReference: 'wallet_ref_001'
  },
  {
    headers: {
      'x-api-key': 'fk_production_DTKUG...',
      'Content-Type': 'application/json',
      'X-Idempotency-Key': 'unique-request-id-12345'
    }
  }
);
```

## Idempotency

Creating a checkout requires an idempotency key. Send either `X-Idempotency-Key` (recommended) or the backward-compatible `Idempotency-Key` header. If both headers are sent, their values must match exactly or the API returns `400 Bad Request`.

Reusing the same key with the same checkout payload returns the original checkout without creating another one. Reusing it with a different payload returns `409 Conflict`. Idempotency keys can contain up to 255 characters and are scoped to your merchant account.

```bash
curl -X POST https://api-production.fossapay.com/api/v1/checkouts \
  -H "x-api-key: fk_production_DTKUG..." \
  -H "Content-Type: application/json" \
  -H "X-Idempotency-Key: checkout-order-10025-v1" \
  -d '{
    "amount": 5000,
    "currency": "NGN",
    "reference": "ORDER-10025",
    "feeBearer": "customer"
  }'
```

<Tip>
  Generate a new, stable key for each logical operation and retain it when retrying after a timeout. A UUID or your own operation identifier works well.
</Tip>

## Error Handling

### Authentication Errors

If authentication fails, you'll receive a `401 Unauthorized` response:

```json
{
  "success": false,
  "message": "Invalid API key",
  "code": "INVALID_API_KEY"
}
```

Common authentication errors:

| Error Code | Description |
|------------|-------------|
| `INVALID_API_KEY` | The API key provided is invalid |
| `EXPIRED_API_KEY` | The API key has expired |
| `MISSING_API_KEY` | No API key was provided |

## Security Best Practices

<AccordionGroup>
  <Accordion title="Store Keys Securely">
    - Never hardcode API keys in your application
    - Use environment variables or secure key management systems
    - Rotate keys regularly
  </Accordion>

  <Accordion title="Use HTTPS Only">
    - All API requests must use HTTPS
    - HTTP requests will be rejected
  </Accordion>

  <Accordion title="Restrict API Key Access">
    - Limit API key permissions to only what's needed
    - Use different keys for different applications or services
    - Monitor API key usage in your dashboard
  </Accordion>

  <Accordion title="Implement Rate Limiting">
    - FossaPay implements rate limiting to protect against abuse
    - Current limit: 100 requests per minute
    - Contact support for higher limits
  </Accordion>
</AccordionGroup>

## Verifying Authentication

Verify your authentication setup with this simple request:

```bash
curl https://api-production.fossapay.com/api/v1/customers \
  -H "x-api-key: fk_production_DTKUG..."
```

**Successful Response:**

```json
{
  "success": true,
  "message": "List of customers retrieved successfully",
  "data": []
}
```
