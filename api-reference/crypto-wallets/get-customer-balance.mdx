---
title: 'Get Customer Wallet Balance'
openapi: '/api-reference/openapi.json GET /api/v1/wallets/crypto/customer/{customerId}/balance'
description: "Retrieve a customer's Solana or Stellar wallet balances"
---

The customer and selected network wallet must belong to the merchant resolved from the production API key. Solana balances can contain SOL, USDC, and USDT; Stellar balances can contain XLM and USDC. Unsupported asset receipts remain visible in wallet transaction history but are omitted from the supported-balance response.

## Path parameter

<ParamField path="customerId" type="string" required>
  FossaPay UUID of the individual customer whose wallet balance will be retrieved.
</ParamField>

## Query parameter

<ParamField query="network" type="string">
  `solana` (default) or `stellar`. Specify `stellar` to retrieve the customer's Stellar wallet.
</ParamField>

## Header

<ParamField header="x-api-key" type="string" required>
  Active production API key belonging to the customer's merchant.
</ParamField>

## Request example

```bash
curl --request GET \
  --url 'https://api-production.fossapay.com/api/v1/wallets/crypto/customer/11111111-1111-4111-8111-111111111111/balance?network=stellar' \
  --header "x-api-key: $FOSSAPAY_API_KEY"
```

## Errors

| Status | Typical cause |
|---|---|
| `400` | Customer or selected network wallet was not found for this merchant |
| `401` | Missing, invalid, or inactive API key |
| `422` | `customerId` is not a valid UUID |
| `5xx` | Temporary provider or platform error |

Use decimal-safe arithmetic and preserve the returned string values. A balance response is a point-in-time view; reconcile transaction state separately.
