## What are webhooks?

FossaPay sends an HTTP `POST` request to your configured webhook URL when an event occurs. Webhooks let your server react to checkout payments, deposits, payouts, and other asynchronous activity without continuously polling the API.

## Webhook envelope

```json
{
  "eventId": "evt_mtwc9i1y_0409d781714d8fa2",
  "eventType": "checkout.completed",
  "data": {
    "checkoutId": "35f5f6fb-0c8d-4e96-ba4a-c04750724ff6",
    "reference": "ORDER-10025",
    "status": "completed"
  },
  "timestamp": "2026-09-11T02:30:14.186Z"
}
```

| Field | Description |
|---|---|
| `eventId` | Unique event identifier. Use it to detect duplicate deliveries. |
| `eventType` | Event name, such as `checkout.completed`. |
| `data` | Event-specific payload. This object is the signed portion of the webhook. |
| `timestamp` | Time the event envelope was created, in ISO 8601 format. |

## Delivery headers

| Header | Description |
|---|---|
| `x-fossapay-Signature` | Lowercase hexadecimal HMAC-SHA256 signature. HTTP header names are case-insensitive. |
| `X-Event-Id` | Same identifier as `body.eventId`. |
| `X-Event-Type` | Same event name as `body.eventType`. |
| `X-Retry-Count` | Present on retry deliveries and indicates the retry count. |

## Verify signatures

FossaPay currently signs the serialized `data` object—not the full webhook envelope—with your webhook secret:

```text
signature = HMAC-SHA256(webhook_secret, JSON.stringify(body.data))
```

The result is encoded as lowercase hexadecimal. Verify it before acknowledging or processing the event.

### Node.js example

```javascript
import crypto from 'node:crypto';
import express from 'express';

const app = express();
app.use(express.json());

function verifyWebhook(body, signature, secret) {
  if (!body || !body.data || !signature || !secret) return false;

  const expected = crypto
    .createHmac('sha256', secret)
    .update(JSON.stringify(body.data))
    .digest('hex');

  const received = String(signature);
  if (expected.length !== received.length) return false;

  return crypto.timingSafeEqual(
    Buffer.from(expected, 'utf8'),
    Buffer.from(received, 'utf8')
  );
}

app.post('/webhooks/fossapay', (req, res) => {
  const signature = req.get('x-fossapay-signature');

  if (!verifyWebhook(req.body, signature, process.env.FOSSAPAY_WEBHOOK_SECRET)) {
    return res.status(401).send('Invalid signature');
  }

  res.sendStatus(200);
  enqueueWebhook(req.body);
});
```

### Python example

```python
import hashlib
import hmac
import json

def verify_webhook(body, received_signature, secret):
    serialized_data = json.dumps(
        body["data"],
        separators=(",", ":"),
        ensure_ascii=False,
    )
    expected = hmac.new(
        secret.encode("utf-8"),
        serialized_data.encode("utf-8"),
        hashlib.sha256,
    ).hexdigest()
    return hmac.compare_digest(expected, received_signature)
```

<Warning>
  The signature input is exactly `JSON.stringify(body.data)`. Do not include `eventId`, `eventType`, or `timestamp` in the signed value. In languages other than JavaScript, serialize compact JSON with the same property order received in `data`.
</Warning>

## Safe processing

<AccordionGroup>
  <Accordion title="Acknowledge quickly">
    Return an HTTP `2xx` response as soon as the signature and basic envelope are valid. Move database updates, emails, and third-party calls to an asynchronous job.
  </Accordion>
  <Accordion title="Handle duplicate deliveries">
    Store `eventId` with a unique database constraint. If the event has already been processed, return `2xx` without repeating fulfillment or crediting.
  </Accordion>
  <Accordion title="Do not depend on delivery order">
    Use the event's checkout or transaction identifiers and current status. Your handler should tolerate retries and events arriving later than expected.
  </Accordion>
  <Accordion title="Reconcile through the API">
    If a checkout webhook is delayed or processing fails, retrieve the checkout by ID or merchant reference before taking action.
  </Accordion>
  <Accordion title="Expect retries">
    Failed webhook deliveries are retried up to five times. `X-Retry-Count` is included on retries.
  </Accordion>
</AccordionGroup>

## Local testing

FossaPay cannot deliver webhooks directly to `localhost`. Expose your local server through a secure HTTPS tunnel and configure the public URL in the dashboard.

```bash
ngrok http 3000
```
