title: Verify Identity
openapi: '/api-reference/openapi.json POST /api/v1/kyc/verifications'
description: 'Look up a Nigerian NIN for ₦120 or BVN for ₦70 per attempt'
---

Retrieves the available person details for a Nigerian NIN or BVN. The endpoint does not compare a submitted name or DOB and does not make a verification decision. Each NIN provider attempt costs **₦120** and each BVN provider attempt costs **₦70**, including attempts that return no person details.

## Headers

<ParamField header="x-api-key" type="string" required>
  An active production FossaPay API key with full permission. The associated business must have completed verification.
</ParamField>

<ParamField header="X-Idempotency-Key" type="string" required>
  A unique key for this logical verification request, up to 255 characters. Retry with the same key and identical body to avoid an additional charge.
</ParamField>

## Body

<ParamField body="method" type="string" required>
  `NIN` or `BVN`.
</ParamField>

<ParamField body="identityNumber" type="string" required>
  The person's 11-digit NIN or BVN. Preserve leading zeros.
</ParamField>

Nigeria is selected automatically. Do not include `country`, names, date of birth, or `consent` in the request body.

## Request

```bash
curl --request POST \
  --url https://api-production.fossapay.com/api/v1/kyc/verifications \
  --header "x-api-key: $FOSSAPAY_API_KEY" \
  --header "X-Idempotency-Key: verify-customer-10025-bvn-v1" \
  --header 'Content-Type: application/json' \
  --data '{
    "method": "BVN",
    "identityNumber": "01234567890"
  }'
```

## Response

HTTP `200` returns the result directly:

```json
{
  "reference": "11111111-1111-4111-8111-111111111111",
  "method": "BVN",
  "charged": true,
  "feeAmount": "70.00",
  "currency": "NGN",
  "person": {
    "identityNumber": "01234567890",
    "firstName": "Ada",
    "middleName": "Ngozi",
    "lastName": "Okoro",
    "dateOfBirth": "1990-05-15",
    "gender": "female",
    "phoneNumber": "08012345678",
    "email": "ada@example.com",
    "address": "12 Example Street"
  }
}
```

`person` returns the identity number and the available person details. Optional fields are `null` when unavailable. The response does not include provider metadata or a verification decision. The `reference` is FossaPay's identifier for the request.

When no usable person details are returned, the full response has the same shape with `person: null`:

```json
{
  "reference": "22222222-2222-4222-8222-222222222222",
  "method": "BVN",
  "charged": true,
  "feeAmount": "70.00",
  "currency": "NGN",
  "person": null
}
```

Both responses represent a charged lookup attempt. Your business decides how to handle the returned details or their absence.

## Idempotency

- An identical completed request with the same key returns the original result and its original fee without another charge, even if the current price has changed.
- Reusing the key with a different request body returns `409`.
- A request still processing may return `409` or `503`. Retry only with the same key and body. If it remains unresolved, contact support with the idempotency key and any returned reference.
- If a request was rejected before verification and no charge was made, correct the issue and use a new key for the new request.

## Errors

| HTTP status | Meaning |
|---|---|
| `400` | Missing or oversized idempotency key, unsupported method, invalid identity number, no active NGN master wallet, or insufficient available balance. |
| `401` | Missing, invalid, inactive, revoked, or non-production API key. |
| `403` | The merchant account is suspended or has not completed business verification. |
| `409` | The idempotency key was reused with different details, or the original request is still processing. |
| `422` | Request body failed field validation. |
| `503` | Verification is temporarily unavailable or a prior request needs reconciliation. Retry the same request with the same key when the outcome is unclear. |
